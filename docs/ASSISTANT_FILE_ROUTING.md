# AETHRION assistant file routing

The protected `POST /assistant/upload` endpoint is the bounded file-input companion
to `POST /assistant`. It classifies the latest task prompt, selects the matching
native specialist, and passes the uploaded file through a short-lived server-owned
temporary path. Caller-supplied filesystem paths are never accepted.

## Multipart request

Required fields:

- `file`: one uploaded file
- `prompt`: task instruction, 1–12,000 characters

Optional field:

- `capability`: explicit specialist selection; when omitted, deterministic
  intent cues in the prompt select the route

Supported mappings and limits:

| Specialist | File types | Maximum |
|---|---|---:|
| AETHRION-VISION | PNG, JPG, JPEG, WebP | 20 MiB |
| AETHRION-ASR | PCM WAV | 25 MiB |
| AETHRION-DOC | PDF, DOCX, TXT, MD, JSON, CSV, LOG | 8 MiB |

Example:

```bash
curl -X POST "$AETHRION_URL/assistant/upload" \
  -H "Authorization: Bearer $AETHRION_API_TOKEN" \
  -F "prompt=Describe this image" \
  -F "file=@scene.png"
```

The endpoint returns the selected capability, delegation metadata, provider,
and specialist result. Temporary upload files are removed after dispatch,
including when specialist dispatch raises an error.

## Security and release behavior

- Authentication is required.
- File extension and leading file signature must match the selected modality (PNG/JPEG/WebP, WAV, PDF, or DOCX); text formats must decode as UTF-8, and JSON must parse.
- Empty and oversized uploads are rejected.
- The multipart upload is closed on every exit path, including invalid extensions and failed specialist dispatch.
- The temporary path is generated by the server; arbitrary client paths are not accepted.
- Specialist handlers remain responsible for SAFE input/output screening and
  model-release checks. Text SAFE cannot inspect image pixels, so VISION remains
  unavailable unless a separate local semantic visual-input verifier is both
  implemented and released. If a required model or safety gate is unavailable,
  the request fails closed with a service-unavailable response.
- This endpoint does not train models, approve datasets, or bypass the native
  model registry.
- IMAGE and 3D are output-generation tasks, not upload routes; VISION, ASR,
  and DOCUMENT are the supported uploaded-input specialists.
- The Hugging Face Space source now includes an **Assistant + Upload** tab
  using the same intent classifier, local specialist router and SAFE-gated
  handlers. The source change is in the GitHub branch; the live Space has not
  yet been deployed or verified.
